# Q1 2026 Security Program — Executive Summary

**ARK STUDIOS Security Team** · Prepared for the leadership team · 15 March 2026

> This report summarises the security work completed over the last two quarters, our current risk posture, the most important open risks, and what we plan to do next. It is written for a non-technical audience; every technical finding in the dashboard has an automatic **attack simulation** you can click through to see how it would be exploited and what damage it could cause.

## Where we stand

We run a continuous security program across our **web platform, API, mobile app, cloud infrastructure and on-chain contracts**. Since September we have completed **eight engagements** spanning vulnerability assessment, smart-contract audit, penetration testing, load testing, network analysis, secure code review and a red-team phishing exercise, and we run a continuous internal bug hunt in between.

Our biggest risks were caught and fixed **before** they could be exploited in production:

- A **critical SQL injection** in the web platform — fixed before launch.
- A **critical reentrancy** in the staking vault that could have drained all user funds — fixed and re-tested before mainnet.
- An **admin authentication bypass** and a **cross-tenant data-access flaw** — both fixed.
- A **hardcoded cloud key** shipped in the mobile app — revoked within the hour, with no unauthorised use.

## Most important open risks

1. **Missing rate limiting on login codes** — could allow two-factor bypass by brute force. *Fix in progress.*
2. **Network segmentation** — the office network can reach the production database directly. *Remediation planned.*
3. **Weak password hashing** — a legacy algorithm that must be upgraded before any breach. *Migration in progress.*
4. **Human factor** — 15% of staff fell for a simulated phishing email. Phishing-resistant passkeys are rolling out now.

## What we built

Beyond finding and fixing issues, the team shipped lasting improvements: the **ARK Sentinel SOC bot** (always-on monitoring), a **secret-scanning CI gate**, a **Semgrep security ruleset** in pull requests, a **Foundry audit harness**, and **load-test SLO dashboards**.

## Roadmap

- Finish the ARKT token upgradeability audit.
- Threat-model the new payment flow before it is built.
- Complete the passkey/MFA rollout and network segmentation.
- Q2 external penetration test to validate all remediation.
